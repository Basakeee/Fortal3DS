01

Scene · Camera · Renderer

Three.js render อะไรก็ตามผ่านสามชิ้นนี้เสมอ — ขาดชิ้นไหนไม่ขึ้นภาพ:

THREE.Scene

คอนเทนเนอร์รากของ scene graph ทั้งหมด — ทุก mesh/light/group ต้องถูก .add() เข้ามาที่นี่ (ตรงหรือผ่าน parent อื่น) ถึงจะถูก render

PerspectiveCamera

รับ (fov, aspect, near, far) — fov หน่วยองศา, aspect ต้องอัปเดตทุกครั้งที่ resize ไม่งั้นภาพจะบิด

WebGLRenderer

ตัวจริงที่คุยกับ GPU — setSize() ต้องเรียกตอน resize ด้วย ไม่ใช่แค่ camera.aspect

Render loop

ไม่มี "auto render" — ต้องเรียก renderer.render(scene, camera) เองทุกเฟรม ผ่าน requestAnimationFrame วนไปเรื่อย ๆ: 

function animate() {
  requestAnimationFrame(animate);
  // อัปเดต transform/animation ตรงนี้ ก่อน render เสมอ
  renderer.render(scene, camera);
}
animate();
WHY

Three.js ไม่ผูก render loop ให้อัตโนมัติเพราะบางแอปไม่ต้อง render ทุกเฟรม (เช่น scene นิ่ง ๆ ไม่มี animation) — การแยกให้ผู้ใช้เรียกเองทำให้คุมเรื่อง performance/battery ได้เอง ไม่เปลืองพลังงานเรียก render() ทิ้งเปล่า ๆ

02

Object3D & Scene Graph

Mesh, Group, Light, Camera — ทุกอย่างสืบทอดจาก Object3D ตัวเดียวกัน เลยมี position / rotation / scale เหมือนกันหมด และต่อกันเป็นต้นไม้ได้ (parent-child) — transform ของ parent จะ "ไหล" ลงไปหา child เสมอ

⚠ Gotcha ที่เจอจริงใน session นี้

object.add(child) ไม่ใช่แค่ "เพิ่มเข้าไป" — มัน ย้าย child ออกจาก parent เดิมก่อนเสมอ (reparent) ถ้า child มี parent อยู่แล้ว ตอนทำ Fortal3DS ตัวเมื่อวาน โค้ดทำ scene.add(boy) แล้วค่อย figures.add(boy, girl) ทีหลัง — boy/girl เลย หลุดออกจาก scene ไปอยู่ใน figures ที่ไม่เคยถูก scene.add() เลย จอเลยว่างเปล่า (เห็นแค่ grid)

Local vs World transform

.matrix คือ transform เทียบกับ parent (local), .matrixWorld คือ transform จริงในโลก (คูณสะสมจาก root ลงมา) — ปกติ engine อัปเดตให้อัตโนมัติตอน render แต่ถ้าต้องอ่านตำแหน่งจริงก่อน render รอบแรก (เช่นตอนคำนวณ Box3) ต้องเรียก object.updateWorldMatrix(true, false) เอง — โชคดีที่ Box3.setFromObject() เรียกให้อยู่แล้วภายใน เลยไม่ต้องกังวลจุดนี้บ่อย

Methodใช้ทำอะไร
.add(...children)ต่อลูก — reparent เสมอ (ดู gotcha ด้านบน)
.remove(child)ถอดลูกออก ไม่ dispose geometry/material ให้ ต้องจัดการเอง
.traverse(fn)วนทุก node ใต้ต้นไม้นี้ (รวมตัวเอง) — ใช้บ่อยตอนหา mesh ทั้งหมดใน group
.userDataที่แปะข้อมูล custom (เช่น car.userData.wheels) — รอด survive ทั้ง add เข้า scene และ export
03

Geometry

ทุก geometry สมัยใหม่คือ BufferGeometry — ก้อนข้อมูลตัวเลขดิบ (position/normal/uv/color) เก็บใน BufferAttribute ส่งตรงเข้า GPU (Geometry แบบเก่าถูกถอดออกจาก core แล้ว)

Attribute ที่ต้องรู้จัก

Attributeความหมาย
positionพิกัด vertex (x,y,z) — attribute เดียวที่ขาดไม่ได้
normalทิศตั้งฉากผิว ใช้คำนวณแสง — ไม่มีแล้ว lighting จะแบนหมด
uvพิกัด texture mapping (0-1)
colorสีต่อ vertex — ต้องเปิด material.vertexColors = true ด้วยถึงจะเห็นผล (ตัว voxelKit.js ใช้ทางนี้ทั้งหมด)

Boilerplate ที่ใช้ซ้ำบ่อย

geo.computeBoundingBox();
geo.computeBoundingSphere();   // ต้องเรียกเองก่อนอ่าน .boundingBox/.boundingSphere
geo.center();                   // เลื่อน geometry ให้ midpoint มาอยู่ที่ local (0,0,0)
geo.translate(x, y, z);
geo.scale(sx, sy, sz);
mergeGeometries([geoA, geoB]);  // จาก three/addons/utils/BufferGeometryUtils.js
WHY .center() สำคัญตอนทำล้อ/แขนหมุน

BoxGeometry ที่ translate ด้วย integer offset (เช่น geo.translate(x+0.5, y+0.5, z+0.5) แบบที่ voxelKit.js ทำ) จะไม่ได้ center ที่ (0,0,0) เอง — ถ้าจะหมุน mesh นั้น (เช่นล้อรถ) ต้อง .center() ก่อน ไม่งั้นมันจะหมุนเยื้องแกนแทนที่จะหมุนรอบตัวเอง

04

Material & สี

Materialตอบสนองแสงไหมใช้เมื่อไหร่
MeshBasicMaterialไม่ไม่สนใจแสงเลย เอาไว้ debug/UI element ใน 3D
MeshLambertMaterialใช่ (diffuse เท่านั้น)ราคาถูก ไม่มี specular highlight
MeshStandardMaterialใช่ (PBR)ค่าเริ่มต้นที่ควรใช้ — มี roughness/metalness (ตัวที่ Fortal3DS ใช้ทั้งหมด)
MeshPhysicalMaterialใช่ (PBR ขั้นสูง)เพิ่ม clearcoat/transmission — หนักกว่า ใช้เมื่อจำเป็นจริง ๆ

Vertex color vs Material.color — เลือกยังไง

สองทางให้สีที่มักสับสนกัน: material.color คือสีทึบเดียวทั้ง mesh, ส่วน vertexColors: true ให้แต่ละ vertex มีสีของตัวเอง (ต้องมี attribute color ในตัว geometry) — voxel ตัวรวมสีหลายสีในก้อนเดียว (เช่น body รถที่มีทั้งสีตัวถัง/กระจก/ไฟ) ต้องใช้ vertex color เท่านั้น

⚠ Gotcha: export format ไม่รองรับ vertex color เท่ากัน

glTF/.glb รองรับ vertex color เต็มที่ แต่ OBJExporter ของ three.js ไม่รองรับเลยสำหรับ mesh (รองรับแค่ point cloud) แล้วก็ไม่เขียนบรรทัด mtllib หรือสร้างไฟล์ .mtl ให้เองด้วย — ถ้า model มีหลายสีในก้อนเดียวแล้ว export เป็น .obj ตรง ๆ สีจะหายหมด ต้องแยกเป็นชิ้นสีเดียวต่อชิ้น ตั้ง material.color + material.name แทน แล้วเขียน .mtl เองคู่กัน (ดูตัวอย่างจริงใน kidMain.js's buildMtlText())

Color space: linear vs sRGB

Three.js (ตั้งแต่ r152+) จัดการ color management ให้อัตโนมัติ — hex color ที่ตั้งผ่าน new THREE.Color(0xff0000) ถูกแปลงเก็บเป็น linear space ภายใน แต่ format ไฟล์อย่าง OBJ's Kd คาดหวังค่าแบบ sRGB — ตอนเขียนสีออกไฟล์เอง ต้อง color.clone().convertLinearToSRGB() ก่อน ไม่งั้นสีจะออกมามืดกว่าที่เห็นในจอ

05

Lights

Lightพฤติกรรม
AmbientLightส่องทุกทิศเท่ากัน ไม่มีเงา ไม่มีทิศทาง — กัน object ด้านที่ไม่โดนแสงหลักดำสนิทเกินไป
DirectionalLightแสงขนาน (เหมือนดวงอาทิตย์) — ทิศทางมาจาก .position ชี้ไปที่ .target (default origin)
PointLightส่องรอบทิศจากจุดเดียว มี decay ตามระยะ — เหมือนหลอดไฟ
SpotLightเหมือน PointLight แต่จำกัดเป็นกรวย (angle/penumbra)

Shadow ต้องเปิดเอง 3 จุด: renderer.shadowMap.enabled = true, light.castShadow = true, และ mesh.castShadow / mesh.receiveShadow ต่อชิ้น — ลืมจุดไหนจุดหนึ่งจะไม่มีเงาขึ้นเลยเงียบ ๆ ไม่มี error เตือน

06

Camera Framing & Controls

โจทย์ที่เจอบ่อยสุด: จะวางกล้องให้เห็น object พอดีโดยไม่ hardcode ตำแหน่งยังไง — ทางที่ Fortal3DS ใช้ทั้งโปรเจกต์คือคำนวณจาก bounding volume แทน: 

const bounds = new THREE.Box3().setFromObject(target);
const center = new THREE.Vector3();
bounds.getCenter(center);
const sphere = new THREE.Sphere();
bounds.getBoundingSphere(sphere);
const radius = sphere.radius;

controls.target.copy(center);
camera.position.set(
  center.x + radius * 1.6,
  center.y + radius * 1.2,
  center.z + radius * 1.6
);
controls.update();
WHY ใช้ Box3 ไม่ใช้ geometry.boundingSphere ตรง ๆ

mesh.geometry.boundingSphere ใช้ได้เฉพาะ mesh ก้อนเดียว แต่พอโมเดลกลายเป็น Group (เช่นตัวรถที่แยกล้อออกมาเป็น mesh อิสระ) ต้องใช้ Box3().setFromObject() ที่รวม bounding ของทุก child ในต้นไม้ ไม่งั้นกล้องจะ frame แค่ body ตัดล้อที่โผล่ออกมาทิ้งไป

OrbitControls

มาจาก three/addons/controls/OrbitControls.js — ให้ผู้ใช้หมุน/ซูม/แพนด้วยเมาส์รอบ controls.target ต้องเรียก controls.update() ทุกครั้งหลังขยับ target หรือ camera.position เอง (ไม่งั้นการเปลี่ยนแปลงจะไม่มีผลจนกว่าผู้ใช้จะลากเมาส์ก่อน)

08

Animation Loop Patterns

Clock คือหัวใจของ animation แบบไม่ผูกกับ framerate — ใช้ delta คูณ ไม่ใช่บวกค่าคงที่ตรง ๆ ทุกเฟรม ไม่งั้นความเร็ว animation จะขึ้นกับ FPS ของเครื่องผู้เล่น: 

const clock = new THREE.Clock();

function animate() {
  requestAnimationFrame(animate);
  const delta = clock.getDelta();       // วินาทีจริงตั้งแต่เฟรมก่อน
  const elapsed = clock.getElapsedTime();

  wheel.rotation.x += angularVelocity * delta;  // ✓ frame-rate independent
  // wheel.rotation.x += 0.05;              ✗ เร็ว/ช้าไม่เท่ากันตามเครื่อง

  car.position.y = baseY + Math.sin(elapsed * speed) * amplitude;

  renderer.render(scene, camera);
}

Gotchas จาก Fortal3DS (ของจริง ไม่ใช่ตำรา)

สามอันนี้เจอเองระหว่างทำ voxel car + character pipeline สัปดาห์นี้ เก็บไว้กันเจอซ้ำ:

1. Object3D.add() reparent ไม่ใช่ copy

scene.add(mesh) แล้วค่อย someGroup.add(mesh) ทีหลัง = mesh หลุดจาก scene ไปอยู่ใน someGroup แทน ถ้า someGroup ไม่เคยถูก add เข้า scene จะได้จอว่างเปล่าแบบไม่มี error — สร้าง group ที่ต้องการก่อน แล้ว add เข้า group นั้นทีเดียว ค่อย add group เข้า scene ทีหลังสุด

2. Collision-free ≠ ดูติดกับตัวสมเหตุสมผล

เช็คว่า voxel สองก้อนไม่ชนกัน (ไม่ z-fight) ไม่พอ — ถ้าให้ระยะห่างคงที่ตลอดทั้งชิ้น (เช่นแขนที่ fix ตำแหน่ง x ตลอดความยาว) เพื่อเลี่ยงจุดที่กว้างที่สุดแค่จุดเดียว จะได้ผลลัพธ์ "ไม่ชนก็จริงแต่ดูลอยห่าง" แทน — ทางที่ถูกคือให้ตำแหน่งขยับตามรูปทรงจริงทีละแถว/ทีละจุด

3. OBJ ไม่ใช่ glTF — vertex color หายถ้าไม่เตรียมตัว

Merge mesh เดียวที่ใช้ vertex color (ปกติสำหรับ glTF) พอ export เป็น .obj แล้วสีหายหมด เพราะ OBJExporter ไม่รองรับ — ต้องรู้ก่อนออกแบบ pipeline ว่าจะ export format ไหน ถ้าต้องรองรับทั้งคู่ ให้แยกเป็น part สีเดียวต่อชิ้นตั้งแต่แรกจะง่ายกว่าแก้ทีหลัง

Cheat Sheet

// Setup ขั้นต่ำสุดที่ต้องมีเสมอ
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(50, innerWidth/innerHeight, 0.1, 100);
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

// Resize ต้องอัปเดตทั้งสามจุดนี้
window.addEventListener("resize", () => {
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(innerWidth, innerHeight);
});

// Dispose ตอนลบ object ถาวร (กัน memory leak — renderer ไม่ทำให้อัตโนมัติ)
mesh.geometry.dispose();
mesh.material.dispose();
